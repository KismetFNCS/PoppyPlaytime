# Custom models (`assets/`)

Put your `.glb` models in this folder and the game will use them in place of its built-in
procedural models. Anything you don't provide keeps the built-in version.

## 1. Name your files after the slot they replace

| File name contains | Slot | What it replaces | Auto-fit |
|---|---|---|---|
| `monster` / `spoolwright` / `creature` | `monster` | the whole creature (legs included) | scaled to 2.9 m tall, feet on the floor |
| `monster_head` / `head` | `monsterHead` | only the mask (the procedural legs and body stay) | 0.62 m tall |
| `hand_left` | `handLeft` | the left (teal) gauntlet | 0.26 m longest side |
| `hand_right` | `handRight` | the right (amber) gauntlet | 0.26 m longest side |
| `tape` / `cassette` / `vhs` | `tape` | the VHS tapes you pick up | 0.2 m longest side |
| anything else | `prop` | nothing: it is placed in the level | native size (1 unit = 1 m) |

If you provide only one hand, it is used for both sides.

## 2. Load them: pick the option that fits how you open the game

Custom models load from this folder through `assets.json`, which needs the game to be served by a local
web server (browsers block a page opened straight from disk from reading other files). The old in-game
loader in Settings and drag-and-drop were removed; any models they had saved in the browser are cleared
when the game starts.

**Running a local web server.** From the repository root:

```bash
python3 -m http.server 8000
```

Then open http://localhost:8000/ (it serves `index.html`). With a server, the game reads
`assets/assets.json` on startup and loads every entry listed there.

## 3. `assets.json` (the manifest)

`assets.example.json` shows every option. File paths are relative to this folder.

```json
{
  "assets": [
    { "file": "monster.glb", "slot": "monster" },
    { "file": "hand_right.glb", "slot": "handRight", "rotate": [0, 90, 0] },
    { "file": "props/barrel.glb", "slot": "prop", "position": [3, 0, -8], "rotate": [0, 45, 0], "fit": 1.2 }
  ]
}
```

| Field | Meaning |
|---|---|
| `file` | path inside `assets/` (`.glb` only) |
| `slot` | `monster`, `monsterHead`, `handLeft`, `handRight`, `tape` or `prop`; if omitted, the file name decides |
| `position` | props only: `[x, y, z]` in metres. Press **F1** in-game to see your current position |
| `rotate` | `[x, y, z]` degrees, applied before fitting. Use it to fix models exported facing the wrong way |
| `fit` | target height in metres (overrides the slot's auto-fit; for props it switches auto-fit on) |
| `scale` | extra multiplier on top of the fit |
| `collider` | props only: `false` lets the player walk through it (default `true`, a box around the model) |

Level landmarks for placing props: the intake lift is around z 0 to 8, the Reclamation Hall around
z −24 to 0, the Pressure Gallery around z −48 to −24, the Spool Foundry around z −92 to −48, and the
freight lift around z −98 to −92. x = 0 is the centre line, and every floor is at y = 0.

## 4. Exporting from Blender (or similar)

- **File → Export → glTF 2.0**, Format: **glTF Binary (.glb)**. Separate `.gltf` + `.bin` files are not supported.
- Keep **+Y Up** on (the default). Apply transforms (Ctrl+A → All Transforms) before exporting.
- **Do not** enable Draco mesh compression. Draco, meshopt and Basis textures are rejected, with a message saying so.
- Facing: the model's **front should face +Z** in glTF (Blender's −Y "front" view exports that way by default).
  If it ends up backwards in-game, add `"rotate": [0, 180, 0]`.
- Hands: fingers pointing **+Z**, palm facing down (−Y).

### What is supported

Triangle meshes, node hierarchies, normals (computed if missing), one UV set, base-color textures (PNG/JPEG
embedded in the `.glb`), base color / metallic / roughness / emissive factors, alpha cutout, and double-sided
materials. **Not yet:** skeletal or keyframe animation (rigged models show in their bind pose), normal maps,
and metallic-roughness or emissive textures. The game still animates the creature as a whole: it walks,
turns, leans, bobs and lunges.

## 5. Checking it worked

- A short message appears at the bottom of the screen for each file loaded or rejected.
- **F1** shows draw counts; **F9** runs the self-test (it loads and removes its own test models and leaves yours alone).

`examples/sample_crate.glb` is a 1 m textured crate you can use to try the pipeline: copy its line from `assets.example.json` into `assets.json` and run a local server.
It was generated by `tools/make_sample_glb.mjs`.
